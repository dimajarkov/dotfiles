# Domain docs

This repository uses a single-context layout:
- Root `GLOSSARY.md` for domain vocabulary.
- `docs/adr/` for architectural decisions.

Before exploring, read the glossary and ADRs relevant to the work.
If those documents do not exist, proceed silently.
Create them lazily when terminology or architectural decisions are resolved.

Use glossary vocabulary in tickets, tests, and documentation.
Surface conflicts with existing ADRs rather than silently overriding them.
