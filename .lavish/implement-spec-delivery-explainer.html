Four different things

A ticket is not a branch, and a branch is not a worktree.

Ticket

A unit of required work and its acceptance criteria.

Commit

A recorded change with a parent history; one ticket can produce several.

Branch

A movable name pointing at a commit.

Worktree

A checkout directory with its own working files and Git index, sharing the repository's history.

Why separate directories?
Two agents writing in the same checkout can overwrite each other's edits or accidentally commit mixed work through the same Git index.
Separate worktrees isolate concurrent writers. They are not necessary merely because two tickets have no dependencies.

Current skill

Isolate every ticket.

One integration worktree plus a separate branch/worktree for each implementer ticket.

  • Parallel code edits have separate files and indexes.
  • Requires branch syncs, mergers, and lease management.
  • Proof-only research may not need this isolation.
Explicitly required by the current step 4.
Your proposed alternative

Serialize edits; commit per ticket.

One integration checkout. Finish and commit A, then B, then newly unblocked C.

  • Preserves ticket-specific history without worker merges.
  • Only one writer edits or stages changes at a time.
  • Read-only exploration and review can still run in parallel.
Valid Git workflow, but requires changing the skill's blanket allocation rule.

Allocation and retention are different policies.
The skill decides to create worker worktrees; your AGENTS.md requires keeping them leased until you explicitly declare the specific job finished.
Returning a verified finished slot for reuse is not the same as deleting/pruning the worktree.
